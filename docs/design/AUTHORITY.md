# Authority, approvals and current scope

## Read in this order

1. The owner's current task and explicit decisions govern the authorized work.
2. The [Game Development Constitution](../project/CONSTITUTION.md) governs scope, experimentation and release discipline.
3. The [Game Design Bible](design-bible.md) owns current design intent. Its provisional labels, working names and open questions remain meaningful.
4. The [Idea Incubator](idea-incubator.md) owns captured ideas and qualification/promotion history. A recorded promotion applies only to its explicitly approved portion.
5. The [design history and research log](../research/design-history.md), [art boards](../reference/art/README.md), imported research and [legacy archive](../archive/README.md) provide evidence and references. They do not create product requirements.

The [Current Release Specification](../project/CURRENT-RELEASE.md) records the owner-authorized local/private MVP envelope. Implementation authorization and measured acceptance remain separate: merged code does not establish that every engineering gate has passed.

## Resolving source overlap

The Bible is the current design owner. Its sections sometimes retain early interview checkpoints followed by later explicit owner decisions. Apply the later explicit decision to the same question; retain earlier text as chronology, not a competing default. Do not infer that a whole feature was approved because one parameter was selected. If two equally current owner decisions materially conflict, flag that specific question without freezing unrelated work.

The research log preserves earlier monetization and scope recommendations that were superseded. The Incubator retains promoted entries so their original uncertainty and scope are traceable. Future changes belong in the actual owning Bible section and the existing Incubator promotion record, not in a second summary specification.

## Working in this repository

Idle Buds is the source of truth from this migration onward. Google Drive originals remain untouched historical backups. Use local document links for ongoing work. New ideas follow capture → qualification → explicit design promotion → release approval → authorized implementation. An import or merge advances none of those product approvals by itself.
