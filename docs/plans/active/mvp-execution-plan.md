## Goal and sources

Build a small complete browser-first idle creature-collection MMO, not an isolated demo. Horizontal completeness, vertical restraint. Gather/craft → earn a catch → train/assign Buds → breed/trade → improve teams and production → reinvest. Players can specialize or play independently. Meaningful first catch around five minutes, full first-session loop and offline setup in 10–15 minutes, daily interaction 5–10 minutes. The plan sequences work without superseding the [Constitution](../../project/CONSTITUTION.md), [authority](../../design/AUTHORITY.md), [Bible](../../design/design-bible.md), [release direction](../../design/bible/12-release-direction.md), [open decisions](../../design/bible/13-open-decisions.md), [architecture](../../architecture/OVERVIEW.md), or [research qualifications](../../research/upstream/engineering/README.md).

Repository baseline: consolidated documentation/research, minimal React/TypeScript/Vite shell and browser smoke, no gameplay, live backend, database or deployment. Enough direction to prepare execution; not every content table, rule, number, license, deployment contract or acceptance threshold is finalized. Resolve only the next necessary decision and verify with a playable slice; do not restart broad interviews.

## Proposed release boundary

Existing approved design/content targets: 15 independent species; 3 zones (Earth plus two portal environments); 3 initial resource tiers of eventual 5; early/midgame content; 4 single portal affinities (working Core, Surge, Bloom, Echo), no elemental effectiveness chart; 7 noncombat skills (Mining, Woodcutting, Fishing, Farming, Cooking, Crafting, Synthesis); conceptual Melee, Ranged, Resonance and Vitality; skill/Bud cap 99 without requiring full level-99 content; 5 Buds plus Tender maximum, no paid/earned combat slots; 24h offline cap with small grace (duration open); NEON FRONTIER selected visual baseline; temporary rights-cleared test assets. No evolution or derived Combat Level.

Proposed must-ship for holistic MVP, subject to one owner approval:
- Persistent account/profile, secure authentication, onboarding, inventory and collection; skill-first navigation, clear locked requirements, desktop/mobile and directional-focus-friendly controls.
- Earned first catch via solo-capable Tender combat; weighted regional encounter pools, automatic prioritized capture-item-or-skip filters, linear crafted/tradeable supplies, one attempt at one target only after victory, consumes one item even on failure; secondary wild eggs. Four IVs (Attack/Health/Gather/Craft), species ability, compatible learned technique, inherited traits, fixed species aptitudes, individual ownership and level. Useful starter specimens; inspect, filter, protect, release; minimum condensation implementation proposed (exact eligibility, benefit and cost need qualification). No recycling faucet.
- All seven skills connected by recipes and recurring consumables: permanent tools/gear, gathering primary and rare secondary drops, fixed routine goods, skill unlocks plus discoverable recipes, multi-recipe queues, storage upgrades. Tender XP from own activity only; Bud labor grants Bud XP, not Tender XP; Tender-gated access, aptitude-based Bud efficiency, one worker per personal node, progression eligibility plus crafted permanent deployment capacity. Initial same-zone production followed by permanent remote deployment. No duplicate tool system for Buds. Alternative permanent combat OR production zone unlocks.
- One deterministic automatic sequential frontline combat engine, provisional Protected Commander (Tender alone fights normally; protected behind Buds until they fall; shared event triggers), Attack/Health, signature/learned effects and earned technique choices, viable Tender-led, Bud-led and hybrid teams. Ordinary repeat PvE resets health between encounters; optional stop between battles. All assigned Buds earn participation XP; Tender trains equipped discipline plus Vitality, optional Resonance support with opportunity cost (provisional XP sharing). Weapons roll bounded Attack and one compatible technique; armor bounded Health and one compatible passive; Crafting mastery and optional enduring maker mark; no mandatory repair, durability or extra affixes.
- Early breeding, eligible same/cross-species pairs, selected primary parent's species preview, most opposite-sex compatible with defined exceptions, independent per-IV parental/random selection and parental/new traits; time-only baseline with optional crafted enhancements; egg then incubation; wild eggs use same hatching system. No third-species special combinations or juvenile stage.
- Global market with fixed-price individual Bud sales, resource listings and funded buy orders, eligible tradeable gear, atomic escrow/settlement/cancel/claim, successful-sale tax; stock-based NPC general store with conservative buyback, higher sale price, bounded stock and gradual essential restocks, no NPC Bud trades. Solo progression with zero player listings remains possible. Quantify faucet risk, bound abuse and preserve early-material demand; no unlimited scripted liquidity assumption.
- Immediate community visibility; early unlocks for participating, first earned Bud before Bud buying; global chat with reporting/mute/block/rate limit and moderation, friends, basic clans with shared progression/bonuses and one asynchronous contribution goal template. Blind async ranked PvP with actual Bud stats, fair matchmaking, immutable defense snapshots, same combat engine and prestige/cosmetic rewards, no exclusive functional power.
- Server-authoritative persisted and offline activities, cap/grace, input/capacity/finite-task constraints, return summaries, retry/reload/reconnect safety; production-ready security, accessibility, operations and recovery appropriate to authorized test and release environments.

Nice to have (never blocks this release): additional cosmetic variants, collection presets/comparisons and earned conveniences beyond basic safety, additional optional guides and visual/audio polish. Not this release: additional species above target (30–50 is a separate first-official-release target), fifth/sixth affinities, resource tiers 4–5, live PvP, clan wars, raids, roguelite modes, fusion, evolution, complex genetics/egg moves, housing, auctions, speculative salvage, specialized capture boosters, extra skills, native clients/Tauri, Steam/Deck distribution, real-money purchases or premium shop. Monetization only after official launch and separate approval. Public beta and initial official release are distinct gates; expansion targets require later qualification, not automatic scope growth.

## Technical implementation contract (proposed detail, choose concrete minimum at M1)

Use approved React/TypeScript/Vite, semantic DOM/CSS, Node 24/npm, one modular Node/TypeScript/Fastify server and PostgreSQL. No Rust/Bevy, ECS, microservices, event bus, Redis, queue platform, custom engine, native wrapper, generic DSL or monorepo tooling unless demonstrated need and approval. Use existing src/game for pure rules and src/data for definitions; keep platform-independent rule functions consumable by server and browser display/test without trusting browser output. Server modules by domain as they appear, not an empty scaffold of every future feature. Prefer typed JSON commands/queries over REST/HTTP; use simplest chat refresh/push mechanism that satisfies measured requirements. Select existing safe auth/session and migration tooling based on requirements, rights and maintenance, not novelty. No vendor lock-in or paid account required by this plan.

Define stable IDs and versioned content definitions for species/affinities, abilities/traits, skills, resources, recipes, gear, zones/encounters; instance IDs for Buds, gear, eggs, listings and matches. Validate references, integer bounds, recipe inputs/outputs, rarity weights and legitimate sources/sinks. Keep content tables separate from calculations. No copied donor formulas/assets. Proposed persistent domain records: accounts/sessions/profiles, skill XP, unlocks, inventory/currency balances, owned Bud/gear instances, assignments/queues, eggs, marketplace/escrow, social membership/messages/contributions, ranked snapshots/results, activity checkpoints and unique command receipts. Implement only records needed in each slice. One current owner per transferable instance; explicit assignment/escrow exclusivity (including breeding/combat/work conflict policy to qualify before M3/M4). Version DB migrations and state/content used for replay; never overwrite only recoverable data.

Server validates identity, authorization, input, eligibility, current version, capacity and costs on every mutation; client never decides rewards, elapsed time, capture/hatch roll, combat outcome or settlement. Use database transactions, constraints, bounded integer quantities and explicit rounding, lock conflicting rows in consistent order, retry bounded serialization/deadlock failures, unique idempotency keys; same operation replay returns same result or safe already-applied receipt. Validate before mutate; no negative quantities, double spend, duplicate ownership or repeated reward. Account sessions are isolated; safe cookies/CSRF where applicable, rate limiting, least privilege, server-only secrets, dependency/license scans. Do not expose hidden genetics seeds or sensitive player data.

Offline: server timestamps/checkpoints and explicit injected clock in pure tests; resolve due activity on access/command and necessary shared-world actions, not one daemon/timer per player. Advance only eligible elapsed time, cap at 24h plus owner-approved grace, stop at inputs/slots/finite task limits, batch safe deterministic work; bounded seeded stochastic outcomes must preserve semantics versus online stepping and allow exact retry. Transactionally persist resulting rewards and checkpoint together. Define deterministic ordering of completion/claim/events and shared locks; no second advancement on retries, refresh, dual tabs or clock changes. One bounded catch-up job only if profiling demonstrates request limits; no speculative worker platform. Reuse the research R01/R03/R13/R21/R30/R31/R34 as test ideas, not adopted code or proven runtime guarantees.

## Acceptance matrix (proposed numerical gates; owner approves before build, tune only through explicit decision)

| Gate | PASS criterion / evidence |
|---|---|
| First session | At least 8 of 10 new testers earn a useful Bud within 5 minutes and set meaningful offline work by minute 15 without facilitator intervention; no guaranteed paid/handed-out catch, no blocker. Retain timings and reasons; small sample is diagnostic only. |
| Routine | At least 8 of 10 testers review outcomes and set their next meaningful activity in 5–10 minutes or less without being forced into one profession; observe at least 3 voluntary return sessions over a 7-day closed test. |
| Breadth | All 15 species, 3 zones, 3 tiers, 4 affinities, 7 noncombat + 4 conceptual combat skills accessible through legitimate paths; each species has signature and use case, each skill has meaningful progression/output, both zone unlock routes work, level cap 99/no reset. Full loop can be completed self-sufficiently with no other listings. |
| Combat | At least 3 distinct viable Tender-led, Bud-led, hybrid team compositions clear a common representative PvE benchmark at comparable progression; deterministic seed replay and all eligible Bud/Tender XP; ordinary repeat health reset, pause/preparation. Catch attempts <=1 per win, no attempts on defeat, exact one-item consumption per attempt. |
| Production & genetics | 100% fixture pass for recipe dependencies, worker/node exclusivity, XP ownership, unlocks, queues, storage/input constraints and remote deployment. Compatible cross-species and same-species breeding/hatch works, inherited and random outcomes demonstrated; unique ownership/claims; at least one crafted enhancement and meaningful equipment variability. |
| Offline | Compare online stepping vs offline on fixed seeds at 0/5min/1h/24h/over cap including grace boundary, empty input/storage/full/finite tasks, reload/clock manipulation, concurrent resume and retry. No excess reward, duplication, lost accepted progress or negative state; same seed/content/version produces equivalent result. |
| Market | Real two-account resource/Bud/gear trades, buy-order funding/matching, tax, cancellation, NPC stock/restock; 100 competing requests for same unique item award exactly one owner and conserve currency/items net of explicit sinks/faucets; retry, failed operation and race fixtures pass; no NPC Bud sale. | Social & ranked | Two+ accounts demonstrate friends, chat/report/block and clan contribution/bonus with no double award. | Client & performance | Built artifact exercised at 1440x900, 390x844 and 844x390 plus keyboard/directional focus; no unreachable critical controls, console errors or unreadable/overflowing critical data. | Product & release | Integrated two-account E2E and at least 10 fresh closed testers over 7 days; collect voluntary return, favorite paths, friction and why players want another session. ## Test, release and recovery

Follow [testing](../../engineering/TESTING.md), [game testing](../../game/testing.md), [assets and saves](../../game/assets-and-saves.md), [release](../../game/release.md) and [delivery](../../agents/delivery.md). CI: existing repo health, npm lint/typecheck/build/test/audit; register new commands only with actual suites. Separate local evidence, hosted CI, human playtest and deployment. Each PR includes affected contract, explicit YES/NO exit criteria, exact commands/results, source hash, known misses and smallest repro/repair. Block merge on relevant failing checks. Scope repairs to observed failures, no weakening tests. Game rules tests use deterministic seeds and injected clocks; no waits for real days. Test migration/recovery, ownership, negative paths and boundaries, not just happy paths. Never import third-party source into runtime from research.

Release ladder after authorization: internal candidate with exact commit/content/schema and reproducible package → closed test environment using rights-cleared temporary assets, backups and data policy → fix defects and rerun full gate → owner-approved public browser beta with privacy/terms/moderation/support/monitoring, explicit reset or migration policy, resource budgets, health checks, DB backup/restore drill, incident/rollback runbook → owner-reviewed official release scope (30–50 species and 5–6 affinities are planning targets to qualify separately, production art/rights, support and sustainable live operations). No real monetization before official launch; separate launch/commerce approval. Do not deploy before environment, budget, target, privacy and release authorization. Use previous tagged build and compatible DB rollback or validated forward migration; pause writes/trading when integrity is at risk, restore rehearsed backup only with authorized recovery, disclose potential loss; never revert binaries against incompatible schema blindly. No destructive player-data reset without policy/approval.
