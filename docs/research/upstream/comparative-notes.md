Methodology contrast (7 games): when a game ships source (Koltera) the whole investigation is source-level; when it is an online IL2CPP title (Idle Clans) the productive path is metadata → class model, assets → strings/loc, and the developer's own public data/API/wiki rather than binary disassembly — and nothing that touches live services. For a compiled-content game (Super Auto Pets) the class model reveals the *architecture* (DSL, resolver, enums) while numbers must come from generated strings and the community wiki, so the evidence tier for balance data drops to STRONG INFERENCE.


Kadomon (Mono build, 2026-11-25): a Mono Unity title is the best case after shipped source — ilspycmd gives readable C# in minutes, and UnityPy with type trees generated from the Managed DLLs (plus a reader for Odin's binary blobs) turns every ScriptableObject into JSON, so balance data and rules are both VERIFIED without any disassembly. The pass took a fraction of the Super Auto Pets effort for a higher evidence tier.

Palworld (UE5 pak, 2026-11-25): an Unreal title with an unencrypted pak is the mirror image of an IL2CPP one — the *content* layer is fully recoverable (CUE4Parse + a current usmap turns every DataTable and DataAsset into JSON, so counts, tables, prices, EXP curves and breeding ranks are VERIFIED) while the *rules* layer sits in a 100 MB+ C++ binary with no symbols, so damage, capture and stat constants stay at STRONG INFERENCE from community testing. The reusable lesson: build the exporter once (see `tools/ue-pak-export/`), and spend the time on the data model, where Unreal games keep most of their balance.

Siralim Ultimate (GameMaker YYC, 2026-11-25): the hardest engine case so far — no bytecode, no symbols, content compiled as code — but YYC leaks names (per-function `gml_Script_*` string), string literals (startup initialisers), variable/builtin slot records and a rigid statement shape for table assignments, so a static decoder recovered the databases and a lifter made Ghidra output readable enough to VERIFY the core formulas. Cost: a day of toolkit building (`tools/gamemaker-yyc/`), reusable for any YYC title; the limit is function size (multi-megabyte trait hooks exceed the decompiler).

Milky Way Idle (web MMO idle, 2026-11-25): like Idle Clans the rules live on a server, but this developer ships the formulas in the client (display-side code plus a prose "Formulas" guide) and a public market API, so most mechanics reach the VERIFIED tier from public static files alone; the content tables come from the community's copies of the login payload, made trustworthy by checking every hrid against the bundle. No binary work at all — the effort goes into reconciling three sources (client code, guide text, community sim).

Koltera 2 (Electron + TypeScript source map, 2026-11-26): the sequel ships the same gift as the first game (embedded sources), so the work is reading code; the reusable step is bundling the original content modules with esbuild through their tsconfig path aliases to dump every table as JSON without re-typing anything. The independent review mattered more than usual here: a one-line reducer check (sanctuary accepts awakened creatures only) and an ignored XP source (a 5-minute expedition) changed the progression story, which is a reminder that reading formulas is not the same as reading the rules that gate them.

Melvor Idle (NW.js wrapper → web client, 2026-11-26): the Steam install is a thin shell, so the real target is the official web client, which serves its game scripts unminified and its base data as plain JSON; downloading those public static files (and not the entitlement-gated expansion packages, and nothing behind a login) gave every core formula at the VERIFIED tier with line references. The engine is the cleanest fixed-step design in the set: one 50 ms tick, timers in ticks, and offline catch-up that is the online tick run in batches sized to a frame budget. The review showed why a model must simulate the state the code carries rather than divide XP by interval: rock HP and respawn cut sustained Mining roughly sixfold, fishing junk and thieving stuns change the others, artisan mastery uses fixed intervals, and two default settings (stop on stun, combat off offline) change what "offline equals online" means in practice.

Melvor Idle 2 (Godot 4 C#, 2026-11-26): a Godot .NET title is close to the Mono-Unity best case: ilspycmd gives readable C# for the game assembly, and the PCK (here a named section inside the signed exe) holds the whole design as one JSON package, so both rules and data are VERIFIED without running anything; the online layer is obfuscated and was left alone. Two lessons from the review carry over to every data-driven game: count what the code actually loads (here `EntityConfig`), not what the data file contains, since alphas ship unwired content; and recompute "identical to the predecessor" claims from the successor's own expression, because a different way of writing the same power (`Pow(Pow(2, 1/7), i)` versus `2^(i/7)`) changed 100 XP thresholds.
