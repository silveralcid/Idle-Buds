# Technical architecture

## Build (VERIFIED)
- **Engine**: Godot 4.7.2 with C# (GodotSharp 4.7.2) on .NET 10.0.15 (`GamesByMalcs.Melvor2.runtimeconfig.json`, `deps.json`); mobile renderer; viewport 1920×1080. Project settings decoded from `project.binary` (`evidence/pck/project_settings.json`): name Melvor2, version **0.11.7**, subversion **alpha**, user dir "Games By Malcs/Melvor Idle 2", autoloads SmartFormatConfig, CloudConfigurationUpdater, LoggingLoader; feature tags `steam`, `dotnet`.
- **Code**: `data_GamesByMalcs.Melvor2_windows_x86_64/GamesByMalcs.Melvor2.dll` (11.8 MB). ilspycmd 9.1 decompiles it to 4 048 C# files (≈668 k lines), of which 618 are an in-game **data editor** (content-authoring forms for every data type). Libraries: Nakama 3.21.2 and Satori 3.21.2 (Heroic Labs online services), Steamworks.NET, Serilog, SmartFormat, ZString, FuzzySharp.
- **Pack**: the PCK is embedded in the 602 MB `Melvor2.exe` at offset 109 411 328 (format v4, relative file base, directory and files unencrypted; the exe is Authenticode-signed: the pack is a named PE section `pck` (raw pointer 109 411 328), and its footer (size + `GDPC`) sits at 602 175 892, just before the signature at 602 175 904, so the pack can be located from the section table or the footer without scanning). 14 865 entries: 4 762 `.import` + 4 558 `.ctex` textures, 3 039 one-byte `.cs` placeholders, 1 137 `.remap`, 779 scenes, 358 resources, audio, fonts, shaders, and the content package `Data/Packages/MelvorBase.json` (15.3 MB) plus gettext locales (`en_GB.po`, `zh_CN.po`, stub `fr.po`). Read with `research/tools/godot-pck/`.
- **Obfuscation**: only the online/account code is obfuscated (namespaces `A`, `C`, `b` with single-letter types: cloud API, Nakama/Satori sessions, Patreon link, news feed). Those files are replaced by stubs in this research copy (`evidence/decompiled/REDACTED_ONLINE_NAMESPACES.txt`); the rest of the assembly is plainly named.

## Engine model (VERIFIED)
- **Physics-tick simulation.** `GameDriver._PhysicsProcess` → `Game.PropagateTick()` → `Tick()` on every `ITickingEntity`. `Constants.TickInterval = 1000/Engine.PhysicsTicksPerSecond`; the project does not set the physics rate, so it is Godot's default 60 Hz (16.67 ms; with Godot's default of at most 8 physics steps per frame, game time slows below 7.5 fps). Every timed action is a `TickTimer` counting `round(ms/TickInterval)` ticks; all base intervals in the data are multiples of 50 ms and map exactly.
- **Entity–component content model.** The game is a set of `GameEntity` objects (one per skill or system, e.g. `MelvorBase:Woodcutting`, `MelvorBase:Bank`, `MelvorBase:TimeAndWeather`) composed of components (Action, Experience, MasteryGuild, Toolbelt, Statistics, Pets…), configured from the data package's `EntityConfig`. Behaviour types (`Goals`, `Triggers`, `Conditions`, `StopOptions`, `ActionUntilX`) are data-addressable classes (`[DataClass(TypeId = …)]`) selected by `"Type": "MelvorBase:…"` in JSON.
- **Reactive stat graph.** Most derived numbers are nodes in a dataflow graph (combat level, for example, is a plain method called from views): classes marked `[StatsClass]` declare `[InputStat]`s, `[ModifierStat]`s (flat/percent/triangle modifiers gathered by context) and static `[StatComputer("Name", deps…)]` functions; a source generator (namespace `SourceGenerators.Stats`) wires `ComputeStatNode`s so a change to any input recomputes only dependants. Formulas such as hit chance, resistance and max hit are tiny pure functions inside this graph.
- **Data-driven formulas.** Even formula choice is data: each `CombatStyle` names its accuracy and evasion level ratios, its max-hit formula type (`StrengthBonus`, `DamageBonus`) and its combat-level ratios.
- **Offline = same tick, off-thread.** Offline/catch-up runs `PropagateTick()` in a `Task.Run` loop, one tick per `TickInterval` of missing time, with the UI paused and a progress counter. Triggers: a save older than 10 s on load; a `SleepDetector` that every 5 s compares wall clock with accumulated physics time and fires at ≥ 10 s drift (≤ 60 s → catch-up, > 60 s → offline mode with a before/after snapshot); max offline time is a stat (base 24 h, modifiers can only raise it). Drift under 10 s within one 5 s window is discarded, not caught up.
- **Time and weather.** A `TimeAndWeather` entity carries day segments (Day 08:00, Sunset 16:00, Night 20:00) and weather (Clear weight 9, Rain 1); time of day has three modes (`TimeOfDayComponent.cs` 99–121, 169–178): the default accelerated cycle (30 game seconds per real second, a 48-minute day starting at 08:00), the system clock, or a fixed hour.

## Persistence and platform (VERIFIED)
- Binary save writer/reader (`Saves/`), one region per entity (`Game.WriteTo` writes each entity id and its region), 5 save slots, autosave every 10 s, separate local and cloud save timers, backups (`BackupSaves`), a `LegacySaveMigrator`, Steam cloud store (`Platforms.Steam/SteamCloudSaveStore.cs`) and a cloud save source behind the obfuscated online layer.
- Steam integration (presence, cloud), logging via Serilog, news panel fed from an external blog, feedback forms via external links.

## Observations
- The architecture generalises Melvor Idle 1's: still one fixed-step tick and one tick function for offline, but typed C#, ECS-style entities, and a dependency-tracked stat graph instead of a global modifier lookup.
- Content authoring is built into the game binary (618 editor files), which suggests the shipped JSON is the editor's output (INTERPRETATION).
- Being alpha, the data contains explicit placeholders ("missing_artwork" icons, an "ALPHA TEST ONLY" bank-slot purchase, generic task descriptions).
