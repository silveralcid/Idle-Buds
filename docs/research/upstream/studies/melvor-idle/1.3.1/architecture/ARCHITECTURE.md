# Technical architecture

## Delivery (VERIFIED)
- **Steam build = thin NW.js wrapper.** `Melvor/package.nw/package.json` ("Melvor Idle" 1.2.2, Games by Malcs Pty Ltd) opens `index.html`, which is a single full-window `<iframe src="https://steam.melvoridle.com">`. Chromium flags: `--disable-raf-throttling --disable-background-timer-throttling --disable-autofill --disable-offer-store-passwords --disable-devtools`. `node-remote` grants Node access to `https://*.melvoridle.com/*`; `greenworks.js` (+ `lib/win64/greenworks-win64.node`, `steam_api64.dll`, loaded by `steamInit.js`) bridges Steamworks (package.json also lists `steamworks.js`, which is not installed); `discord.js` drives Discord rich presence (pushed every 15 s); `main.js` clears an `EOSAccessToken` from localStorage on close. The 259 MB `assets/media` folder is a local image cache; `SavesDir/` only holds `steam_autocloud.vdf`.
- **The game itself is a web client**: `steam.melvoridle.com` serves the same codebase as the browser version: 143 TypeScript-compiled, unminified scripts under `assets/js/built/` (127 190 lines, build 12097, `gameVersion = 'v1.3.1'`), third-party libraries (PIXI, Dexie, fflate, petite-vue, dagre, fuse, tippy, PlayFab SDK) and JSON data packages under `assets/data/` (data version 528). The research copy was fetched without logging in (`evidence/client/SOURCE.txt`).

## Engine model (VERIFIED)
- **Fixed 50 ms tick.** `game.startMainLoop()` uses `setInterval(loop, 50)`; `processTime()` runs `floor(elapsed/50)` ticks per loop (capped at 1 728 000), so the simulation rate is independent of frame rate and timer jitter. `tick()` calls `passiveTick()` on every passive ticker (classes defining it: farming, township, mining rocks (respawn), harvesting, combat manager and characters), `activeTick()` on the single active action (a skill or combat), then `combat.checkDeath()`. Golbin Raid replaces the tick body with its own.
- **One active action.** The player runs exactly one active skill or combat at a time; passive systems tick alongside. Every timed thing is a `Timer` counting ticks (`maxTicks`, `ticksLeft`), serialised in the save.
- **Offline = fast-forwarded online.** When a loop sees a gap ≥ 60 s (closed game, sleep, suspended tab), it switches to the offline loop: the same `tick()` runs in batches whose size is re-tuned every frame to fill ~95 % of a 50 ms frame (leaving time for garbage collection), showing a progress bar, until the gap (max 24 h) is consumed. There is no separate offline formula; what changes is which actions keep running: entering the offline loop stops combat unless the player enabled offline combat (default off, behind five confirmations), stops locked-skill actions, and never runs Golbin Raid. The RNG is unseeded `Math.random`, so offline has the online distribution, not the same outcomes.
- **Rendering is decoupled**: systems set `renderQueue` flags during ticks and `render()` consumes them once per online loop; the offline loop does not render at all.
- **Data-driven registry.** All content is registered from JSON packages into namespaced registries (`namespaceRegistry.js`; ids like `melvorD:Normal_Logs`, `melvorF:…`, `melvorTotH:…`, `melvorAoD:…`, `melvorItA:…`). Packages can add objects and `modifications` patch existing ones, which is the same path mods use.
- **Modifier system.** Bonuses are declared as data (`modifiers`, 570 modifier definitions in the Demo package) and queried by id with scope (`game.modifiers.getValue("melvorD:masteryXP", query)`); equipment, pets, prayers, potions, agility obstacles, astrology, township and mastery mostly contribute through the same tables (`modifiers.js`, `modifierTable.js`, `statProvider.js`), with some hard-coded exceptions (e.g. Stormsnap and the Slayer Crossbow in `player.js` 476–480, 2235–2245).
- **Official modding.** `mod.js` (6 558 lines) implements a mod manager with mod.io integration, local mods loaded by dynamic `import()` into the game's context with a per-mod context API (not a sandbox), game-version tags and per-mod error attribution (errors in ticks are mapped back to the responsible mod).

## Persistence (VERIFIED)
- `saveWriter.js`: a binary writer with a header that maps namespaced ids to compact numeric ids, then the body; the buffer is zlib-compressed with fflate and base64-encoded (`saveWriter.js` 707–716). Legacy JSON saves (gzip + base64, `save.js` 313) are still readable through migration code (`serializeSave.js`, 2 882 lines of old-format conversion).
- Autosave every 10 s, cloud checks every 10 s (`game.js` 3401–3405); local storage through localStorage/IndexedDB (Dexie), cloud through Melvor Cloud/PlayFab accounts (`cloudManager.js`, `cloud.js`). Character slots and gamemodes are separate saves: Standard (Demo package), Hardcore and Adventure (Full package) are current; CHAOS and the three speedrun modes are past their `endDate` and shown as "Discontinued" (`characterSelect.js` 715, `characterSelectMenus.js` 51–66); Ancient Relics is referenced in code (`ancientRelics.js`) but its gamemode is not in these two packages.
- No save was read and no account was used in this research.

## Entitlements and packages (VERIFIED)
`cloudManager.js` 508–531 always registers `melvorDemo.json`; registers `melvorFull.json` only if `hasFullVersionEntitlement()`; event packages (Birthday 2023, April Fools 2024) when active; and the three expansions (Throne of the Herald, Atlas of Discovery = `melvorExpansion2`, Into the Abyss) only with their entitlements. This research downloaded the Demo and Full packages (the owned Steam base game) and deliberately did not fetch the expansion or event packages; expansion mechanics are described only from the client code that ships to everyone.

## Observations
- The architecture is the clean version of what Koltera 2 approximates: a single fixed-step clock in the save, timers in ticks, one tick function for both online and offline, and render flags instead of re-rendering per step.
- The wrapper's background-throttling flags matter: without them Chromium throttles background `setInterval` (to about 1 Hz, and much further after long background periods), so ticks would be processed in large catch-up batches; with them the 50 ms loop keeps running. The local media folder is used first by `assets.js` 36–85, with the CDN as fallback.
- Content and code are separable: balance changes ship as data versions (528) independently of the script build (12097).
