# Architecture (VERIFIED unless marked)
## Build
GameMaker Studio 2 project `SiralimUltimate`, config `Default`, bytecode version 17, runtime **2024.1400.0.879** (string in the exe), window 1280×720. Compiled with the **YoYo Compiler (YYC)**: `data.win` (904 MB) carries assets only — GEN8/OPTN/LANG/EXTN/SOND/SPRT/BGND/SCPT/GLOB/SHDR/FONT/OBJT/ROOM/TPAG/STRG/TXTR (118 MB textures)/AUDO (777 MB audio) — and **no CODE/VARI/FUNC chunks**; all GML is native x64 in `SiralimUltimate.exe` (166 MB, 143 MB `.text`, 385 555 `.pdata` entries). `options.ini` confirms the LLVM-Windows (YYC) target and lists extension sections. Extensions: BigNumbers 0.9.1 (`big_mult`/`big_add` used in every stat and XP formula), GMLive fallback (dev hot-reload stub, `GMLive/` folder shipped), Steamworks 2.1.5, Text_Inputs 1.1.3, Tile_Based_Fog_Of_War 1.1.0, Virtual_Joy 1.0.0. Third-party GML libraries visible in script names: Scribble (text), PPFX (post-processing), ATLA (boot), thylacine_* helpers, `vm_impl_*`/`gml_parser_*` (an embedded GML interpreter used by GMLive/macros).
## Where things live
- **Code**: 8 831 named native functions mapped: 2 740 `gml_Script_*` (1 170 game scripts — `scr_` 797, `bc_` 221, `inv_` 152 — the rest are libraries: `vm_` 330, `gml_` 299, `mc_` 125, `compile_` 107, `live_` 94, `scribble_` 62…), 4 510 object events, 1 581 `gml_GlobalScript_*` 238–245-byte stubs that wrap the same script names (so the unique game-function count is ≈5 700, not 8 831). Names survive because every YYC function loads its own `gml_Script_<name>` string for the call stack. Largest: `scr_DatabaseAchievementMain` 7.1 MB, `scr_DatabaseAchievementFulfillment` 4.0 MB, `bc_CreatureCast` 3.9 MB, `bc_EventDamage` 3.1 MB, `scr_DatabasePerks` 2.8 MB, `scr_DatabaseCreature1–4` 8.6 MB total.
- **Content**: not data files but **code** — `scr_Database*` scripts assign `global.<table>[i][j] = literal` row by row (creature, passive, spell, perk, mat, skin, quest, accessory, rune, cooking, tiers, titles, NPCs, decorations, achievements). They were decoded statically (`tools/gamemaker-yyc/yyc_db_decode.py`) into `evidence/exe/db_decoded/databases.json`.
- **Text**: 24 localization CSVs beside the exe (Tag, Notes, English + 14 other languages; traits 4 341 rows, achievements 10 570, items 3 220, ui 3 073, decorations 2 775, creatures 1 612, spells 1 494, lore 1 376, perks 1 322, personality 1 120, quests 1 062…). Database rows reference text through `lcz("L_…")` keys; the game loads the CSVs at runtime (`localization_override` folder is honoured, per the 2.0 notes), which is why they ship as plain text.
- **Variables**: each GML variable/builtin has a static `{name*, id}` record in `.data` (16 170 recovered: `var_level`, `var_hp`, `var_critconstant`, `var_fuse2`, `var_plus` (gene strength), `var_personality`, `var_slot`, `fn_sqrt`, `fn_floor`, `fn_ceil`…).
- **Objects/rooms**: 1 160 objects (`obj_*`, `gui_*`, PPFX renderers), 79 rooms (`preload_room`, `ATLA_boot_room`, `titlemain`, `castle_throneroom`, realm rooms, `ending`), 12 801 sprites, 1 598 sounds, 53 fonts, 47 shaders, 1 timeline.
## Runtime model (STRONG INFERENCE from script names and decompiled code)
Creatures are instances with per-creature variables (`critconstant` = database row, `fuse2` = second fused row or −1, `plus` = gene strength, `personality`, `xp`, `hp/hpmax`, `attack/intelligence/defense/turnspeed`, `slot` = 0 player side / >0 enemy side, `item` = artifact, `gems`, `relic`, `tome_*`). `scr_UpdateCreature` recomputes `hpmax/attack/intelligence/defense/turnspeed` from `scr_GetCreatureStat(crit, "health"|…)`; battle-time values go through `crit_attack/crit_defense/crit_intelligence/crit_speed` (each ~75 KB of trait/perk/condition modifiers). Battle flow: `bc_Turn` → `bc_CreatureStartOfTurn` (1.7 MB of trait hooks) → action (`bc_CreatureAttack` 384 KB, `bc_CreatureCastSpellGem`, `bc_SpellDamage` 706 KB) → `bc_EventDamage` (3.1 MB) → `bc_OnAttack`/`bc_OnDefend`/`bc_OnHeal` → `bc_CreatureEndOfTurn`. Every trait is hand-written GML inside these hooks (no trait DSL), which is why the hook functions are megabytes long.
## Save / network
Single-player; Steam only for achievements/cloud (`Steamworks_x64.dll`). No anti-tamper beyond the compiled build. Saves are local (`save_Stats`/`load_Stats`, `scr_SandboxLoad`).
