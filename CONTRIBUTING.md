# Contributing

Read [AGENTS](AGENTS.md), [authority and scope](docs/design/AUTHORITY.md), then only the applicable owner in [docs/INDEX](docs/INDEX.md). Work on an isolated branch from current `main` and preserve unrelated changes.

New feature ideas go to the [Idea Incubator](docs/design/idea-incubator.md). Design promotion, release scope and implementation approval are separate. This foundation does not authorize gameplay or establish that the BEAT BAES gate is satisfied.

Use [development setup](docs/engineering/DEVELOPMENT.md), [code quality](docs/engineering/CODE-QUALITY.md), [testing](docs/engineering/TESTING.md) and [delivery](docs/agents/delivery.md). Run scoped checks during edits and relevant full checks before review. Keep the one canonical owner synchronized. Report exact evidence, source, environment and limitations; do not substitute a docs check for runtime behavior.

Use the PR template, explain the concrete problem and resulting behavior, and disclose meaningful risk or missing coverage. Never force-push shared history, bypass protections, publish unapproved art/code, or deploy without applicable authorization. Preserve source notices and attribution. Versioning/release preparation follows [the game release guide](docs/game/release.md).
