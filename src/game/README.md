# Game rules

The game rules are pure TypeScript and take server time and seeded randomness as inputs. The server commits the resulting state and command receipt together. The player view removes the private seed, counters and unhatched genetics.

Activity completion uses one chronological scheduler for online and offline progress. Simultaneous breeding completion precedes work, then activity worker IDs are sorted. A reconcile simulates at most 24 hours and shifts unfinished deadlines by discarded time, preserving visible remainder. Jobs consume inputs and award output at completion. A valid new activity replaces the worker's incomplete work; failed validation leaves it intact. Gather and patrol orders repeat by default. Buds work independently, with at most one assigned Bud per production skill plus the earned total worker limit. Tender and Bud may use the same source. Paused and blocked jobs retain their assignment. Formation, work and breeding commitments are mutually exclusive. Ranked defense uses a separate immutable snapshot.

Shared inventory counts each fungible item type once and each unequipped gear instance once. Stack quantity has no gameplay cap; safe integer validation still applies. Equipped gear, Buds and eggs have separate ownership/capacity rules. Sell escrow reserves return capacity. A completed reward that cannot fit remains in a bounded pending slot for its Tender or skill lane; it cannot be lost or rerolled by stopping, replacing work or returning offline. Missing inputs/space are recoverable blocks, distinct from a player pause.

Save schema 2 is separate from combat rules version 1. The schema-1 migration preserves inventory even above the new capacity, retires remote-work restrictions with a one-time refund, and retains any refund above the wallet limit for later delivery. Server persistence validates the migrated state before committing it. Unsupported future save versions are rejected.

Combat is provisional Protected Commander with bounded simultaneous frontline hits and three typed effects. Both PvE and PvP use the same resolver. Immutable opening formations and typed events drive local turn playback; replay controls cannot award rewards or change server timing. Historical results without opening snapshots retain a log fallback. Account-tailored balance, effect viability and real playtest outcomes still require measurement.
