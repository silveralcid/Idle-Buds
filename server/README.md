# Future authoritative API

The approved direction is Node.js/TypeScript/Fastify and PostgreSQL, with one modular server owning time, rewards, creature ownership and economy settlement. No backend code, database, schema, deployment or dependency is needed for this non-game foundation.

Add the smallest real server boundary when a gameplay milestone is authorized. Use transactional updates and real integration/concurrency tests for persistence and economy. Never accept client-computed rewards as authority. Architecture and open implementation choices are documented in [the overview](../docs/architecture/OVERVIEW.md).
